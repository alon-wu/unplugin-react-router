# API 参考

## 插件工厂（Vite 入口 —— 推荐）

```ts
import reactRouter from 'unplugin-react-router/vite'

reactRouter(options?: Options): VitePlugin
```

通用的 `unplugin` 工厂是包根目录的默认导出，各打包器也有专用子路径：

```ts
import reactRouter from 'unplugin-react-router'          // createUnplugin 实例
import reactRouter from 'unplugin-react-router/webpack'   // Webpack 适配（直接调用）
import reactRouter from 'unplugin-react-router/rollup'    // Rollup / Rolldown
import reactRouter from 'unplugin-react-router/esbuild'   // esbuild
// reactRouter.vite(options) / reactRouter.webpack(options) / …
```

Rollup/rolldown/Webpack 的 watch 模式由打包器自身驱动：每次重建都会重新执行
插件的 `buildStart`（即一次新的扫描），因此页面文件的增删在 watch 重建时自动
生效。Vite 开发服务器则需要事件驱动（见 `watch` 选项）。

## `Options`

所有选项均为可选。

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `routesFolder` | `string \| RoutesFolderOption \| Array<string \| RoutesFolderOption>` | `'src/pages'` | 被扫描以查找页面文件的文件夹（**不支持** glob 模式；请用 `exclude`/`extensions`/`filePatterns` 过滤） |
| `extensions` | `string[]` | `['.tsx', '.jsx']` | 视为页面文件的后缀。必须以点开头且非空。匹配最长者胜出。 |
| `exclude` | `string[]` | `[]` | 相对每个被扫描文件夹的 picomatch glob（例如 `['**/ignored/**']`） |
| `layoutFile` | `string \| false` | `false` | 布局特殊文件名（不带扩展名，如 `'layout'`）。开启后 `layout.tsx` 成为所在目录路径段的布局组件；位于路由文件夹根时成为包裹所有路由的无路径布局。启用期间该名字被保留（不能作为普通页面）。 |
| `dotNesting` | `boolean` | `false` | 把文件名里的点展开为嵌套静态路径段（`users.create.tsx` → `/users/create`，不产生 UI 嵌套）。关闭时点是字面字符（`a.b.tsx` → `/a.b`）。 |
| `root` | `string` | `process.cwd()` | 项目根目录；所有相对路径都相对于它解析 |
| `dts` | `boolean \| string` | auto | 为虚拟模块生成环境声明（含 `AppRoutePath`/`RouteParams` 等类型面）。`false` 表示禁用；字符串为输出路径（相对于 `root`）。当能解析到 `typescript` 时默认开启。 |
| `logs` | `boolean` | `false` | 调试输出（扫描树、文件写入） |
| `watch` | `boolean \| 'polling'` | `!process.env.CI` | 开发期页面增删的检测方式：`true` 挂接到打包器/dev-server 文件监视器（有则用，没有则回退轮询）；`'polling'` 强制使用轮询扫描器（用于打包器 watcher 事件不可靠的场景，如部分 Vite 8/Rolldown 环境）；`false` 完全关闭（结构性改动需重启 dev server）。 |
| `_inspect` | `boolean` | `false` | @internal —— 为 `vite-plugin-inspect` 兼容性保留（不带 `\0` 前缀） |

## `RoutesFolderOption`

用于 `routesFolder` 数组中（也可单独使用）。

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `src` | `string` | — | 要扫描的文件夹（**必填**）。不是 glob。 |
| `path` | `string` | `''` | 添加到该文件夹每条路由的静态（或 `[param]`）路径前缀。可包含 `/`。不能以 `/` 开头。末尾的斜杠会被去除。 |
| `extensions` | `string[] \| (existing) => string[]` | global | 对全局列表的逐文件夹覆盖 / 扩展 |
| `exclude` | `string[] \| (existing) => string[]` | global | 对全局列表的逐文件夹覆盖 / 扩展 |
| `filePatterns` | `string[] \| (existing) => string[]` | none | 逐文件夹**正向** glob 过滤（相对该文件夹 `src` 的路径、含扩展名）。提供后，只有匹配其中任意模式的文件才是页面文件；空数组会报错（无文件可匹配）。 |

### 示例

```ts
reactRouter({
  routesFolder: [
    'src/pages',
    {
      src: 'src/admin/pages',
      path: 'admin',
      exclude: ['**/hidden/**'],
      filePatterns: ['**/*.page.tsx'],   // 只把 .page.tsx 当页面
    },
    // parameterised prefix: every route of this folder becomes /docs/:lang/…
    // (the [lang] segment is parsed like a directory segment)
    { src: 'src/i18n', path: 'docs/[lang]' },
  ],
})
```

> 前缀会创建不含组件的父级记录：子路由经由它们渲染，它们**不是**布局。
> 若需要在带前缀的路径处使用布局，可将文件夹前缀与 `index.tsx` 配合使用。

## 虚拟模块 `unplugin-react-router/routes`

```ts
import { routes } from 'unplugin-react-router/routes'
import routesDefault from 'unplugin-react-router/routes'

// both are RouteObject[]
```

- 无前缀的模块 id：`unplugin-react-router/routes`。
- 内部解析为 `\0unplugin-react-router/routes`（Vite 虚拟模块）。
- 生成的源码刻意使用纯 JS（模块 id 没有扩展名，打包器会将其解析为 JS；仅 TS 支持的语法将导致失败）。
- 类型来自插件写入的环境声明（见下一节）。

模块的运行时形态：

```js
export const routes = [ /* RouteObject literals */ ]
export default routes
```

刻意**不引入运行时依赖**：模块只包含路由表和你页面文件的动态 `import()`。`react-router` 仅由环境声明以类型方式导入。

## 生成的文件

### `typed-routes.d.ts`（默认位于项目根目录）

```ts
/* eslint-disable */
/* prettier-ignore */
// @ts-nocheck
// Generated by unplugin-react-router. DO NOT MODIFY THIS FILE.
// Add this file to your tsconfig "include"/"files" entry if it is not picked
// up automatically (default tsconfigs often include every `*.d.ts` under root).

declare module 'unplugin-react-router/routes' {
  import type { RouteObject } from 'react-router'

  export const routes: RouteObject[]
  export default routes

  // ---- generated typed surface (from src/pages) ----
  export type AppRoutePath =
    | "/"
    | "/about"
    | "/users/:id"
    | "/*"

  export interface AppRouteParams {
    "/": Record<string, never>
    "/users/:id": { "id": string }
  }

  export type RouteParams<P extends AppRoutePath> = P extends keyof AppRouteParams
    ? AppRouteParams[P]
    : Record<string, never>

  export interface RouteConfig {
    path?: string
    caseSensitive?: boolean
    handle?: unknown
  }

  export type LoaderData<T extends (...args: never[]) => unknown> = Awaited<
    ReturnType<T>
  >
}
```

在 `buildStart` 期间以及每次重新扫描后、内容发生变化时写入。通过 `dts: false` 禁用，通过 `dts: 'src/ambient.d.ts'` 修改输出位置。若你的 tsconfig 没有自动包含项目根下的 `*.d.ts`，请把它加进 `include`。

## 公开的 TypeScript 类型

从包根目录导入（仅类型，无运行时开销）：

```ts
import type {
  Options,
  RoutesFolder,
  RoutesFolderOption,
  RoutesContext,
  ServerContext,
  TreeNode,
  SegmentKind,
  TreeOptions,
  PageRouteConfig,
} from 'unplugin-react-router'
```

| 类型 | 位置 | 说明 |
| --- | --- | --- |
| `Options` / `RoutesFolder` / `RoutesFolderOption` | `src/options.ts` | 用户选项（上文） |
| `RoutesContext` | `src/core/context.ts` | 插件上下文 API（`scanPages`、`getRoutes`、`getRoot`、`setServerContext`）—— 用于嵌入自定义工具 |
| `ServerContext` | `src/core/context.ts` | 最小的服务器契约（`invalidateRoutes`、`reload`） |
| `TreeNode` / `SegmentKind` / `TreeOptions` | `src/core/tree.ts` | 路由树节点模型与可选约定开关 |
| `PageRouteConfig` | `src/core/routeConfig.ts` | `export const route` 的类型 |

## 错误

所有错误都在扫描期间抛出，带有 `[unplugin-react-router]` 前缀，并在相关时附上出错的文件路径。确切消息如下：

| 消息（片段） | 原因 |
| --- | --- |
| `"extensions" cannot be empty.` | `extensions: []` |
| `Invalid extension "X".` | 扩展名缺少前导 `.` |
| `routesFolder "X" path prefix cannot start with "/".` | 文件夹前缀以 `/` 开头 |
| `"filePatterns" cannot be an empty array` | 空数组会使任何文件都不匹配 |
| `"layoutFile" must be a plain file name` | `layoutFile` 含扩展名/非法字符 |
| `directories cannot be named "index".` | 目录字面名称是 `index` |
| `splat segments … cannot be directories.` | 目录名为 `[...x]` |
| `optional segments … cannot be directories.` | 目录名为 `[[x]]` |
| `unsupported segment "X".` | `[id]+`、`prefix-[id]`、`[a][b]` 等无法用 React Router 表达（含目录可选兜底） |
| `segment "X" contains characters (:, *, ?)` | 静态段与 React Router 路径语法冲突 |
| `route groups must be directories` | 文件名为 `(x)` |
| `a splat route ("[...x]") cannot contain children.` | 兜底路由下嵌套文件 |
| `Duplicate index file for "X"` | 两个 index（含可选参数文件与显式 index 并存） |
| `Duplicate layout file for segment "X"` | 两个文件同时声称同一布局（同名文件 / `layout.tsx`） |
| `dot-nesting cannot express empty segments` | `a..b` |
| `dot-nesting only supports plain static names` | 点内出现 `(` `)` 等结构字符 |
| `route group "X" cannot combine a layout file with an index layout` | `(x)/layout.tsx` 与 `(x)/index.tsx` 并存 |
| `route config "path" overrides are only supported on leaf page files` | index/布局/可选文件的 `path` 覆盖 |
| `route config "caseSensitive" cannot apply to an index route` / `is ambiguous on an optional segment file` | 语义不明的覆盖 |
| `… only literal values are supported …` | `export const route` 含计算表达式 |
| `… must be an object literal` / `unknown key "X"` / `duplicate key` / `duplicate \`export const route\`` | `route` 导出格式错误 |

错误以下列形式呈现：

- 开发服务器 / 构建失败并显示 Vite 覆盖层（它们从 `buildStart` / 重新扫描时抛出），
- 在测试树规则时表现为测试失败。

> 其他任何意外的扫描错误，在 `logs: true` 时通过日志回调上报，否则会像上文那样导致构建失败。
