# API 参考

## 插件工厂（Vite 入口 —— 推荐）

```ts
import reactRouter from 'unplugin-react-router/vite'

reactRouter(options?: Options): VitePlugin
```

通用的 `unplugin` 工厂是包根目录的默认导出：

```ts
import reactRouter from 'unplugin-react-router' // createUnplugin instance
// reactRouter.vite(options) / reactRouter.rollup(options) / …
```

## `Options`

所有选项均为可选。

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `routesFolder` | `string \| RoutesFolderOption \| Array<string \| RoutesFolderOption>` | `'src/pages'` | 被扫描以查找页面文件的文件夹（**不支持** glob 模式；请用 `exclude`/`extensions` 过滤） |
| `extensions` | `string[]` | `['.tsx', '.jsx']` | 视为页面文件的后缀。必须以点开头且非空。匹配最长者胜出。 |
| `exclude` | `string[]` | `[]` | 相对每个被扫描文件夹的 picomatch glob（例如 `['**/ignored/**']`） |
| `root` | `string` | `process.cwd()` | 项目根目录；所有相对路径都相对于它解析 |
| `dts` | `boolean \| string` | auto | 为虚拟模块生成环境声明。`false` 表示禁用；字符串为输出路径（相对于 `root`）。当能解析到 `typescript` 时默认开启。 |
| `logs` | `boolean` | `false` | 调试输出（扫描树、文件写入） |
| `watch` | `boolean` | `!process.env.CI` | 启动仅限开发环境的轮询，检测页面文件夹中新增/删除的文件 |
| `_inspect` | `boolean` | `false` | @internal —— 为 `vite-plugin-inspect` 兼容性保留（不带 `\0` 前缀） |

## `RoutesFolderOption`

用于 `routesFolder` 数组中（也可单独使用）。

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `src` | `string` | — | 要扫描的文件夹（**必填**）。不是 glob。 |
| `path` | `string` | `''` | 添加到该文件夹每条路由的静态（或 `[param]`）路径前缀。可包含 `/`。不能以 `/` 开头。末尾的斜杠会被去除。 |
| `extensions` | `string[] \| (existing) => string[]` | global | 对全局列表的逐文件夹覆盖 / 扩展 |
| `exclude` | `string[] \| (existing) => string[]` | global | 对全局列表的逐文件夹覆盖 / 扩展 |

### 示例

```ts
reactRouter({
  routesFolder: [
    'src/pages',
    { src: 'src/admin/pages', path: 'admin', exclude: ['**/hidden/**'] },
    // parameterised prefix: every route of this folder becomes /docs/:lang/…
    // (the [lang] segment is parsed like a directory segment)
    { src: 'src/i18n', path: 'docs/[lang]' },
  ],
})
```

> 前缀会创建不含组件的父级记录：子路由经由它们渲染，它们**不是**布局。
> 若需要在带前缀的路径处使用布局，可将文件夹前缀与 `index.tsx` 配合使用。

## 虚拟模块 `unplugin-react-router/routes`

```ts
import { routes } from 'unplugin-react-router/routes'
import routesDefault from 'unplugin-react-router/routes'

// both are RouteObject[]
```

- 无前缀的模块 id：`unplugin-react-router/routes`。
- 内部解析为 `\0unplugin-react-router/routes`（Vite 虚拟模块）。
- 生成的源码刻意使用纯 JS（模块 id 没有扩展名，打包器会将其解析为 JS；仅 TS 支持的语法将导致失败）。
- 类型来自插件写入的环境声明（见下一节）。

模块的运行时形态（v0.1）：

```js
export const routes = [ /* RouteObject literals */ ]
export default routes
```

刻意**不引入运行时依赖**：模块只包含路由表和你页面文件的动态 `import()`。`react-router` 仅由环境声明以类型方式导入。

## 生成的文件

### `typed-routes.d.ts`（默认位于项目根目录）

```ts
/* eslint-disable */
/* prettier-ignore */
// @ts-nocheck
// Generated by unplugin-react-router. DO NOT MODIFY THIS FILE.
declare module 'unplugin-react-router/routes' {
  import type { RouteObject } from 'react-router'
  export const routes: RouteObject[]
  export default routes
}
```

在 `buildStart` 期间以及每次重新扫描后、内容发生变化时写入。通过 `dts: false` 禁用，通过 `dts: 'src/ambient.d.ts'` 修改输出位置。

## 公开的 TypeScript 类型

从包根目录导入（仅类型，无运行时开销）：

```ts
import type {
  Options,
  RoutesFolder,
  RoutesFolderOption,
  RoutesContext,
  ServerContext,
  TreeNode,
  SegmentKind,
} from 'unplugin-react-router'
```

| 类型 | 位置 | 说明 |
| --- | --- | --- |
| `Options` / `RoutesFolder` / `RoutesFolderOption` | `src/options.ts` | 用户选项（上文） |
| `RoutesContext` | `src/core/context.ts` | 插件上下文 API（`scanPages`、`getRoutes`、`startWatcher`、`stopWatcher`、`setServerContext`）—— 用于嵌入自定义工具 |
| `ServerContext` | `src/core/context.ts` | 最小的服务器契约（`invalidateRoutes`、`reload`） |
| `TreeNode` / `SegmentKind` | `src/core/tree.ts` | 路由树节点模型 —— 供自定义代码生成消费方使用 |

## 错误

所有错误都在扫描期间抛出，带有 `[unplugin-react-router]` 前缀，并在相关时附上出错的文件路径。确切消息如下：

| 消息 | 原因 |
| --- | --- |
| `"extensions" cannot be empty. Please specify at least one extension.`<br>（扩展名列表不能为空，请至少指定一个扩展名。） | `extensions: []` |
| `Invalid extension "X". Extensions must start with a dot.`<br>（扩展名 "X" 无效，扩展名必须以点开头。） | 扩展名缺少前导 `.` |
| `routesFolder "X" path prefix cannot start with "/".`<br>（路由文件夹 "X" 的路径前缀不能以 `/` 开头。） | `path` 以 `/` 开头 |
| `"file": directories cannot be named "index". Put an index file inside the parent directory instead.`<br>（目录不能命名为 "index"，请改为在父目录中放置 index 文件。） | 某个目录的字面名称就是 `index` |
| `"file": splat segments ("[...x]") cannot be directories. Use a [...rest].tsx file inside a directory instead.`<br>（splat 段（"[...x]"）不能是目录，请改为在目录内使用 `[...rest].tsx` 文件。） | 目录名为 `[...x]` |
| `"file": unsupported segment "X". Only whole-segment params ([id]), whole-segment splats ([...rest]) and static names are supported. Optional ([[id]]), repeatable ([id]+) and partial (prefix-[id]) segments cannot be expressed with React Router path syntax.`<br>（不支持的段 "X"。只支持整段参数（[id]）、整段 splat（[...rest]）与静态名称；可选段（[[id]]）、可重复段（[id]+）与部分段（prefix-[id]）无法用 React Router 的路径语法表达。） | 参数/splat 解析后残留 `[`、`]` |
| `"file": segment "X" contains characters (:, *, ?) that conflict with React Router path syntax. Rename the file/folder.`<br>（段 "X" 含有与 React Router 路径语法冲突的字符（:、*、?），请重命名该文件/文件夹。） | 静态段中出现 `:`/`*`/`?` |
| `"file": route groups must be directories (e.g. "(name)/index.tsx"). A single file cannot be a group.`<br>（路由组必须是目录（例如 "(name)/index.tsx"），单个文件不能构成组。） | 文件名为 `(x).tsx` |
| `"file": a splat route ("[...x]") cannot contain children.`<br>（splat 路由（"[...x]"）不能包含子路由。） | 文件嵌套在 splat 文件之下 |
| `Duplicate index file for "X": a and b`<br>（目录 "X" 的 index 文件重复：a 与 b。） | 同一目录下有两个 index 文件 |
| `Duplicate layout file for segment "X": a and b`<br>（段 "X" 的布局文件重复：a 与 b。） | 两个文件与同一目录同名 |

错误以下列形式呈现：

- 开发服务器 / 构建失败并显示 Vite 覆盖层（它们从 `buildStart` / 重新扫描时抛出），
- 在测试树规则时表现为测试失败。

> 其他任何意外的扫描错误，在 `logs: true` 时通过日志回调上报，否则会像上文那样导致构建失败。
